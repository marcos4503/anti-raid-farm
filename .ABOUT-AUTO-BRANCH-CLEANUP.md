### What is the "AUTO-BRANCH-CLEANUP.bat" script?

This repository contains multiple Branches. If the Branches contain `.gitignore` files, it's common to encounter a rather annoying problem when switching between active Branches in the repository cloned locally on your machine. This problem usually causes files/folders ignored by the `.gitignore` file of the previous Branch to be placed in the now active Branch when switching from one active Branch to another, thus "cluttering" it.

For example, let's say, now, we currently have Branch `B` active. This Branch contains the following files/folders:

- /honda/
- /mazda/
- /toyota/
- /subaru/
- /.gitignore
- /nissan.jpg
- /mitsubishi.mp3
- /suzuki.png
- /yamaha.gif

And now, within the `.gitignore` of our Branch `B`, we have the following...

```md
# Foldes ignored...
mazda
toyota

# Files ignored...
nissan.jpg
yamaha.gif
```

After "Committing" this `B` Branch and "Pushing to Origin", and then switching to our Branch `A`, you'll notice that folders `mazda` and `toyota` and files `nissan.jpg` and `yamaha.gif` will remain there, along with the files from Branch `A`, since they are being ignored by Branch `B`. Although this is expected behavior in Git, it can be a bit annoying.

---

To solve this problem, the script `AUTO-BRANCH-CLEANUP.bat` was created.
After you clone this repository locally on your machine and then run this script on your Windows system with Git installed, the following will happen:

- The script `AUTO-BRANCH-CLEANUP.bat` will retrieve scripts present in this repository, in `.github/hooks` and then, inject these scripts into the `.git/hooks` directory, **ONLY** for this repository. The `.git` is a folder that exists and is hidden, but exists inside any repository cloned of Internet.

The `AUTO-BRANCH-CLEANUP.bat` only needs to be run once. It will only need to be run again if you delete this repository from your machine and clone it back to your machine in the future.

Once script `AUTO-BRANCH-CLEANUP.bat` has been executed and the Hooks have been successfully injected into the `.git` folder of this repository, locally, then whenever you interact with this repository using Git on your machine, Git will run the Hooks in the `.git` folder of this repository. The Hooks, in turn, will run commands `git clean -fdX` and `git clean -fd`, ensuring that whenever you switch between active Branches in **THIS** repository, on your machine, there are no leftover "garbage" files between the active Branch switches. This saves your workflow, keeping it clean, avoiding conflicts and confusion, and improving clarity.

> [!WARNING]
> For script `AUTO-BRANCH-CLEANUP.bat` and the `Hooks` that it installs in this repository, locally on your machine, to function as expected, all Branches of that repository must have identical `.gitignore` files.

---

This is the flowchart of what happens when you switch between Branches in this repository, cloned on your machine, after running `AUTO-BRANCH-CLEANUP.bat`:

- Branch A is active. `[>>]` * *you switch to Branch B* * `[>>]` Git on your PC swaps the files currently in this repository, hiding the files from Branch A and leaving only the files from Branch B.  `[>>]` Git calls the Hooks installed in the ".git" folder of this repository and then removes any remaining junk files from Branch A, leaving only the files you expect from Branch B. 

**That's all!** All of this happens exclusively within this repository, cloned on your machine. This will not affect anything outside of this repository.

---

### How can I implement this system in other repositories?

It's simple! Just copy files `.ABOUT-AUTO-BRANCH-CLEANUP.md` and `.AUTO-BRANCH-CLEANUP.bat`, and folder `.github/hooks` to your repository! These files and folders only need to be copied to the main Branch, the first Branch that someone who clones the repository will have access to.

> [!NOTE]
> Remember that for everything to work properly, all Branches must have the same `.gitignore` file.
